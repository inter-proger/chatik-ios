# Правила разработки

## Работа с git

- Основная ветка, куда сливаются изменения, — `develop`. Напрямую в `develop` не коммитим.
- Каждая задача делается в отдельной ветке `feature/<тема>`, ответвлённой от актуального `develop`.
  - Если ветки для задачи ещё нет — перед началом работы её нужно создать.
  - Если на момент начала работы текущая ветка не пустая (`git log develop..HEAD` показывает коммиты) — подсветить это и предложить выбор: сначала смержить эти изменения в `develop` или создать для задачи отдельную ветку.
- Ветка задачи вливается в `develop` через pull request. После коммита — спросить, нужно ли создавать pull request.

## Порядок разработки по умолчанию

1. **Документ с планом.** В `docs/` описывается документ с планируемыми изменениями и добавляется в таблицу в `README.md`. По документу предлагаются улучшения, вносятся замечания, подсвечиваются решения с плохой практикой. Вносятся корректировки.
2. **Ревью документа.** В отдельной вкладке (сессии без контекста предыдущего шага) проводится ревью документа. Замечания исправляются только после подтверждения.
3. **Реализация.** Реализуется описанный в документе функционал.
4. **Ревью реализации.** В отдельной вкладке (сессии без контекста) проводится ревью реализованного функционала. Замечания исправляются только после подтверждения.
5. **Коммит и pull request** в `develop` (pull request — после подтверждения, см. выше).
