# Постраничный список `PaginatedList`

22.10.2026 · Mikhail Kuzmin

Статус: описание реализованного.

## Назначение

`PaginatedList<Item>` (`Common/Pagination`) — состояние постраничного списка для ViewModel: элементы, флаги загрузки и всё, что нужно для бесшовной подгрузки страниц. Сейчас им пользуется экран создания личного диалога ([users-cache.md](users-cache.md)). Список переписок и лента сообщений раньше тоже строились на нём, но перешли на сервисы с кэшем в БД (`ConversationListService`, `MessagesListService`).

`@MainActor @Observable`, `Item: Identifiable`, `Item.ID: Hashable`.

## Контракт

Как загружается страница, знает владелец: он передаёт загрузчик в каждый вызов. Список не хранит загрузчик между вызовами и не знает про сервисы.

```swift
typealias Load = (PaginationContext) async throws -> PaginatedListPage<Item>
typealias Cached = () async -> [Item]
```

| Тип | Что в нём |
| --- | --- |
| `PaginationContext` | `loadedCount` — сколько элементов уже получено с сервера (для API со сдвигом), `cursor` — курсор предыдущей страницы (для API с `maxId`); `isFirstPage` |
| `PaginatedListPage<Item>` | `items`, `hasNext`, `nextCursor` (`nil` — API работает сдвигом) |
| `PaginationOutcome` | `.applied` — страница применена; `.superseded` — ответ устарел, ни список, ни ошибку он не касается; `.failed(Error)` — владелец решает, как показать ошибку |

Наблюдаемое состояние: `items`, `isLoadingFirstPage`, `isLoadingNextPage`, `isEmpty` (пусто и первая страница не грузится), `contains(id:)`.

## Операции

### `refresh(cached:load:)` — первая страница

Открытие экрана, pull-to-refresh, смена поискового запроса.

- Прежние элементы остаются на экране до ответа; ответ заменяет список целиком, пагинация начинается заново.
- Начатая подгрузка следующей страницы отменяется, её опоздавший ответ отбрасывается.
- **Кэш.** Если передан `cached` и список пуст, кэш читается **параллельно** с запросом (сеть не ждёт БД) и показывается до ответа. Кэш, прочитанный позже ответа, отбрасывается — даже если страница пустая. При ошибке загрузки кэш остаётся. Кэш не участвует в пагинации: счётчик и курсор от него не меняются. Перед возвратом чтение кэша дожидается, чтобы не оставлять висящих задач.
- **Отмена** (`CancellationError` или отменённый сетевой запрос — новый поиск отменил прежний) — не ошибка: итог `.superseded`, список и пагинация не меняются, владелец ничего не показывает.
- Ошибка: список прежний, но `hasMorePages = false` — следующая страница ушла бы со сдвигом от неактуальной выдачи.

### `prefetchNextPageIfNeeded(currentItem:load:onOutcome:)` — следующая страница

Вызывается из `onAppear` строки. Грузит, если строка — в последних `prefetchThreshold` (по умолчанию 5), страницы ещё есть и ничего не грузится. Флаг `isLoadingNextPage` поднимается до старта задачи, чтобы повторные появления строк не запускали вторую загрузку. Задача удерживает загрузчик (а с ним и владельца) до своего завершения.

`loadNextPage(load:)` — сама загрузка; владельцы её напрямую не вызывают (только тесты). Ошибка останавливает пагинацию до следующего `refresh`: иначе при недоступном сервере прокрутка превратилась бы в поток запросов и сообщений.

### `syncFirstPage(load:)` — сверка начала списка

Например, после переподключения к WebSocket, когда события могли потеряться. Флаг первой страницы не поднимается, идущие загрузки не отменяются.

- **Страница стыкуется со списком** (за ней есть ещё элементы, и её последний элемент уже в списке) — вклеивается в начало; элементы списка, которых в ней нет, остаются после неё; сдвиг растёт на число новых элементов, курсор и `hasMorePages` прежние — подгрузка продолжается с прежнего места.
- **Иначе** (возможен разрыв, страница последняя, идёт `refresh` без ответа) — список заменяется страницей, как при `refresh`; идущие `refresh` и подгрузка становятся устаревшими.
- Ошибка — список не меняется.

## Как отбрасываются устаревшие ответы

Номер загрузки `generation` растёт при каждом `refresh` и замене списка. Ответ, пришедший для прежнего номера, возвращает `.superseded` и ничего не меняет. Флаг `isLoadingFirstPage` снимает только актуальная загрузка. `appliedFirstPageGeneration` помнит, к какой загрузке уже применена первая страница, — по нему поздний кэш не затирает ответ.

## Дубликаты

Между запросами список на сервере может сдвинуться. При дописывании страницы элементы, которые уже есть в списке, пропускаются, но `loadedCount` растёт на полный размер страницы — сдвиг следующей страницы считается по выдаче сервера, а не по показанному.

## Пример владельца

```swift
func loadFirstPage() async {
    let query = searchText
    let outcome = await list.refresh { context in try await loadPage(context, query: query) }
    if case .applied = outcome { listedQuery = query }
    show(outcome)
}

private func show(_ outcome: PaginationOutcome) {
    guard case .failed(let error) = outcome else { return }
    notifications.showError(ErrorMessages.message(for: error))
}
```

`CreateSingleConversationViewModel` передаёт курсор `context.cursor` как `maxId` в `/users/getList` и возвращает `nextMaxId` как `nextCursor`.

## Тесты

`PaginatedListTests`: `refresh` — успех, ошибка с сохранением элементов, устаревший ответ, сброс контекста после подгрузки, отмена идущей подгрузки; подгрузка у конца, вдали от конца и на последней странице; дубликаты не дописываются; ошибка подгрузки останавливает пагинацию; `isEmpty` во время загрузки; `syncFirstPage` — вклейка, разрыв, последняя страница, ошибка, во время `refresh` и `refresh`, начатый во время сверки; кэш — показ до ответа, загрузка без ожидания кэша, поздний кэш отбрасывается, остаётся при ошибке, не читается при непустом списке, не сдвигает контекст следующей страницы.
